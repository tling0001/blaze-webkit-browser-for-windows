# WebKit Browser for Windows

A native Windows desktop browser with a WinUI 3 interface and the upstream WebKit Windows port (WinCairo).

## Engine requirement

This project embeds **WebKit**, not Chromium, Gecko/Firefox, Edge WebView2, Electron, or CEF. The WinUI application hosts WebKit's public Windows WKView C API through a small C++/Win32 bridge.

The upstream Windows port is an x64 development/testing port rather than a regularly released consumer runtime. This project pins an exact WebKit revision and builds it from source in GitHub Actions. It must remain labelled a testing build until the engine build, clean-machine package, security-update process, and end-to-end browser tests are all verified.

## Technology

- WinUI 3 / Windows App SDK, C#, MVVM, CommunityToolkit.Mvvm
- Native C++ bridge to WebKit's WinCairo WKView
- Windows x64 only (the upstream Windows port does not currently provide an ARM64 target)
- GitHub Actions: pinned engine build, MSIX package, versioned GitHub Release

## Implemented browser shell

- WinUI 3 MVVM project generated by the official WinApp CLI winui-mvvm template
- Native child-window hosting for WebKit WKView; no WebView2 fallback
- Address/search, back/forward/reload/stop and home navigation
- Multiple tabs with per-tab native WebKit views and shared website data store/context
- Persistent session restore, browsing history and bookmarks
- Downloads routed through WebKit's download client into the Windows Downloads folder
- Per-site geolocation and notification permission decisions; camera/microphone are denied until device-selection support exists
- Privacy settings for JavaScript, automatic images, cookie/cache/site-data clearing
- Configurable tab-strip placement above or below the navigation toolbar

## Build and release

See [.github/workflows/build-windows.yml](.github/workflows/build-windows.yml). The workflow:

1. Checks out the pinned WebKit revision and enables Windows long paths.
2. Builds the x64 WinCairo port and native WebKitHost.dll.
3. Stages the WebKit runtime as a CI artifact.
4. Runs WinUI Gallery/API discovery checks and packages the app using winapp package.
5. Publishes a signed x64 MSIX, public test certificate, and install instructions as a versioned GitHub Release.

Use [Scripts/bump-version.ps1](Scripts/bump-version.ps1) to increment the -port.N version, update the numeric MSIX identity version, and add a dated release-note entry.

## Known testing limitations

- The upstream WinCairo port's release cadence and security servicing are not equivalent to WebKit's regularly released Apple/Igalia ports.
- Camera and microphone access is denied; a device picker and per-device permission model are not yet implemented.
- Popup/new-window handling, JavaScript dialog UI, certificate exception UI, and broader browser security hardening still need implementation and testing.
- A successful GitHub Actions build and clean Windows installation are required before calling the package usable.
